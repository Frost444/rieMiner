# rieMiner Cuda

rieMiner Cuda is a very experimental Riecoin GPU miner. As the name suggests, only (recent) Nvidia Cards are supported for now.

The main Mining Code is being Machine (aka AI) Generated by [Wizz13150](https://github.com/Wizz13150) from the Gapcoin Community with which we maintain close ties. Credit is due to everyone who wrote anything that has been used for training Codex model and producing the initial Cuda Code. Given the unknown sources, we are unable to properly license rieMiner Cuda for now.

We merely did a few cleaning up and adjustments, publishing it here to provide access for everyone to new breakthoughs in Riecoin Mining. It may not always be the latest and most efficient code, inquire Wizz13150 about it or follow the Dev Channel in the Riecoin Discord. We aim is to completely rewrite the Code so that it eventually becomes licensable and as clean and simple as possible like the original rieMiner CPU Miner. Meanwhile, those interested in improving the efficiency can work with Wizz.

The present Code is intended to Build and run on Debian and can probably be adjusted for other Distributions. A working Windows Version does exist, please directly inquire Wizz about it. Supporting Windows here is a task for later.

## Comparison with Original rieMiner (CPU)

Functionnality is very limited. Only Pooled Mining is supported for now with only a very small subset of the original rieMiner's options configurable. It at least does the job of earning more RIC than with a CPU.

At Difficulties 1100-1200, we measured about 3x Speedup of a 3060 over a 9950X under real conditions. Given the currently limited implementation, we have not performed more detailed studies of the performance such as the behavior at different Difficulties or with different Constellation Lengths. The Algorithm seems to break past around Difficulty 1280 when trying to mod the Difficulty Offset.

Viability of Riecoin CPU Mining will depend on several factors such as whether the GPU Miner can still be significantly improved (or if the CPU one could be improved), whether future CPUs will benefit from better generational improvements than GPUs, how a Hard Fork altering Constellations requirements could affect the efficiencies, or simply Riecoin's Price.

## Requirements

- Recent Debian x86-64; Python 3.11 or newer.
- NVIDIA GPU with compute capability **8.6 or newer**. AMD/OpenCL is not supported.
- An NVIDIA driver compatible with CUDA 12.8.
- At least 3 GB free space for generated data and temporary output; reserve more for retained logs. A GPU with 6 GB or more memory is recommended.
- Mining Pool Details

## Build on Debian

Source Code:

```sh
git clone https://github.com/RiecoinTeam/rieMiner.git -b Cuda
```

### Install Dependencies

Run

```sh
bash setup-debian.sh build
```

or inspect the Script and installs yourself the Dependencies. The script uses Debian12's Boost.JSON1.81 development package or Debian13's default Boost.JSON development package. It does not install a driver or add NVIDIA repositories. Boost.JSON links statically, eliminating a version-specific Boost shared-library requirement at runtime. GMP and OpenSSL remain distro-managed runtime libraries.

Install CUDA12.8 toolkit using [NVIDIA's Debian instructions](https://docs.nvidia.com/cuda/archive/12.8.0/cuda-installation-guide-linux/index.html).

### Build

```sh
export CUDACXX=/usr/local/cuda-12.8/bin/nvcc
"$CUDACXX" --version
BUILD_JOBS=2 bash build-gpu.sh
```

### Run

Run some checks and generate an initial Config File

```sh
bash setup-debian.sh runtime
bash setup-debian.sh check
python3 cli/riecoin-gpu/riecoin_cli.py --list-devices
python3 cli/riecoin-gpu/riecoin_cli.py --init-config "pool.json"
```

Edit the generated `pool.json` and `pool.account.conf`. Set your pool host, port, payout address, worker/account and password consistently in both files.

Generate some precomputed data once (approximately 1.7 GB):

```sh
python3 cli/riecoin-gpu/riecoin_cli.py --prepare-data .
```

Finally, start Mining:

```sh
python3 cli/riecoin-gpu/riecoin_cli.py --mine --console table --gpu 0 --config "pool.json" --data-dir "data/riecoin" --basis "backend/riecoin-prime-inverse-cache-v1/154529a28f6b8356b2c6a20635a29d1f878b836bf63388a74f615c5d36e42ca7.rcpi" --state-dir "$HOME/.local/state/horizon-riecoin/gpu0" --session-seconds 3600 --duration 0
```

Device 0 is an example, use your actual index or UUID. With one GPU, `--gpu` may be omitted; with several, select explicitly.

## Dashboard

Rich's maintained Live/Layout/Table/Panel components provide a full-screen, resizable display. `--console auto` selects the table on a terminal and append-only lines when redirected. `--console lines` is suitable for logs; `--no-color` disables colors. At small sizes, an explicit resize notice replaces the table while mining stays controlled.

- **Speed:** actual production-counter differences over an approximately five-second interval. No fixed warm-up phase, artificial startup delay or fabricated maximum.
- **Average · 60 s:** rolling active-work throughput. A partial window displays its actual observed duration. A new work item resets it. Preparation before the first production sample is excluded, so this is not an end-to-end rate including setup.
- **PRP/s:** Q0 probable-prime tests divided by cumulative GPU execution time in that kernel for current work. It is a component average, not pipeline wall-clock speed.
- **r · Q0/Q1:** the current-work survivor ratio. Exact r* and Q7 are separate and appear only if verified telemetry provides them.
- **Shares:** accepted, sent, rejected, stale, errors and pending pool replies; totals and rolling 5 min / 1 h / 24 h windows. An asterisk marks a partial observation. Windows contain only events observed in this run; they are not extrapolated or claimed to persist across restarts.
- Pool endpoint, authorization state, run duration, block height, work target, GPU and capability remain visible when space permits. No password is displayed.

Structured journals remain in your private state directory. Finding a candidate, sending a share, receiving acceptance and finding a block are different events.
